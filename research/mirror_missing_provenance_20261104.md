## Failure mode

The existing `reconcile_event_mirror` deliberately rebuilds a **missing** mirror from authoritative SQLite using `_replace_atomic(path, expected)`. This is appropriate for recovery from a missing cache/audit copy, but the regenerated bytes are not independent historical authentication. If both an original mirror and a trustworthy external digest are unavailable, an altered SQLite row cannot be distinguished from an original one by regeneration alone. This is a trust-boundary limitation, **not evidence that BEAN was attacked**.

## Executed synthetic control

Python 3 standard-library `sqlite3`, in-memory table `events(id INTEGER PRIMARY KEY, summary TEXT)`:

```python
import sqlite3
c = sqlite3.connect(":memory:")
c.execute("CREATE TABLE events(id INTEGER PRIMARY KEY, summary TEXT)")
c.execute("INSERT INTO events VALUES(1, 'original')")
before = list(c.execute("SELECT id, summary FROM events"))
c.execute("UPDATE events SET summary='altered' WHERE id=1")
after = list(c.execute("SELECT id, summary FROM events"))
assert before != after
print(before, after)
```

Observed: `[(1, 'original')]` versus `[(1, 'altered')]`; assertion passed. This verifies that a snapshot generated *only* from current SQLite has no access to prior contents. It does **not** execute BEAN's full reconciler, simulate a filesystem crash, or establish tampering in a real installation.

## Paired evaluation to run before any production proposal

1. Unchanged baseline: create synthetic events, reconcile JSONL, delete mirror, restart/reconcile; require byte-identical reconstruction and explicit `rebuilt_missing` status.
2. Negative control: create synthetic events and original mirror, alter SQLite offline, delete mirror, restart/reconcile; verify the new mirror reflects altered DB and **must not be labeled authenticated history**.
3. Detection control: retain the original mirror while altering SQLite; require `AuditMirrorError` on mismatch without silently overwriting either copy.
4. Optional integrity comparator: store a signed or independently protected digest *outside* both SQLite and JSONL, then repeat negative control; require mismatch detection. Plain hash in the same writable directory is not an independent trust anchor.
5. Recovery and restart: test tail truncation, power-loss boundaries, repeat reconciliation, multi-process writers, and evidence provenance. Record every negative result.

Acceptance criterion: any future audit UI must distinguish `recovered_from_sqlite` from `independently_verified`; never infer the latter from successful reconstruction. Keep corrections append-only as discussed in #273-#277 and do not mutate old JSONL rows. No AGI claim follows from this experiment.
