# BEAN full-core repeatability ledger (experimental)

Two full Core suite reruns of source commit `a0c63d9fad7c128457f8fcda6685332de39094d7`, based on current code (not the older research-branch code): [GitHub Actions run 39521813810](https://github.com/danieloculus0-bot/BEAN/actions/runs/39521813810), **attempts 2 and 3**. Each attempt ran the existing full-core regression on Ubuntu and Windows with Python 3.10 and 3.12. All eight CI jobs succeeded. For each attempt the four jobs jointly reported 2,698 passing test cases, 10 skipped test cases, and 208 passing subtests (subtests counted separately). Test coverage includes current BEAN Core capabilities, persistent memory, reasoning, evidence, ranking, integration and current core skill-related behavior exercised by the existing tests. It is **not** a full end-to-end external-LLM or connected Axiom/Jetson test.

**Persistent artifacts:** `matrix_event_log.csv.gz` has 8 independently identified job outcomes. `matrix_scoreboard_pass_2.json` and `matrix_scoreboard_pass_3.json` are per-pass compact snapshots; `matrix_scoreboard.json` is the combined index. The original 34-row research baseline and 21-row anticipatory replay event ledger remain intact elsewhere on this branch. JUnit individual-case details live in each run's GitHub Actions artifacts, and were separately extracted for the Ubuntu/Python 3.12 runs into a locally deliverable 1,354-case-event archive; those details are not duplicated in the eight-row GitHub summary log.

**Scope limitation:** the standard workflow runs `pytest bean/tests`; four additional `test_*.py` files under `experiments/` are not included. The workflow deliberately skips certain cross-repository or local-only tests. This does not establish that 100% of the repository's test files have run. Passing repeatability checks is not evidence of learning or verified autonomous skill improvement.

No production files, learning weights, deployed services or systems were changed. No integration was performed. Gzip decompression of the matrix event log round-tripped to the exact original CSV, which has SHA-256 `95624bf727a5bdb78c385e84339c5566c86e7c05196b315f2d9894fcddf8612a`.
