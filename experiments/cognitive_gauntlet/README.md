# BEAN Cognitive Gauntlet (isolated experiment)

This experiment stays off main. It has **not** implemented AGI or executed
OpenNARS, Hyperon, PLN, Voyager, Letta or DreamerV3 as opponents.

## Current measured challenge

The first CPU-only pilot compares an independent-evidence pool with a
newest-claim baseline, using the **same** simulated observations, truth labels,
budget and seeds. Both may fail. Run:

    python -m unittest bean.tests.test_cognitive_gauntlet -v
    python -m experiments.cognitive_gauntlet.runner

The runner writes a gzip JSON receipt preserving every synthetic case, every
incorrect prediction, comparator errors, seeds and SHA-256 payload digest.
The test suite checks deterministic replay and score reconciliation.

This first comparator is a *prototype*, not BEAN Core's live world-model
runtime. No external competitor is installed or measured in this pilot.
The existing real BEAN-versus-Aider coding contest remains in
experiments/agent_arena and is not replaced.

## Proposed next rounds (not completed)

- OpenNARS / PLN: compare source-aware truth revision and inference, including
  conflicting evidence and correlated sources, to BEAN's existing claim model.
- Hyperon: test typed relationship query and provenance versus current claims.
- Voyager: test curriculum and retained-skill retrieval against BEAN native skills.
- Letta: compare context recall, consolidation and restart continuity.
- DreamerV3: compare world prediction and control on matched observation/action
  environments with matched compute budgets and actual installed runtimes.

These projects have incompatible interfaces and computational requirements.
An experiment is not an external head-to-head until both actual systems execute
the same held-out tasks. Maintain their exact revisions, licenses and adapters.


## Source reference and implementation boundary

The revision equations in `cognition.py` were checked against
[OpenNARS-for-Applications `src/Truth.c` at dc4efd0](https://github.com/opennars/OpenNARS-for-Applications/blob/dc4efd0abd520cdb79bf53bfa3c285ebb24f2e8a/src/Truth.c)
(MIT licensed, Copyright 2020 OpenNARS authors). The prototype converts
confidence to evidential weight `w=c/(1-c)`, sums independent weights, then
computes expectation `0.5+c*(f-0.5)`. BEAN's source grouping is an additional
conservative heuristic: only the most recent event per named origin contributes
to a prediction, while every original event remains in the receipt.

The implementation is a small Python approximation of those equations,
**not** an installation or execution of OpenNARS. The newest-claim comparator
is likewise a deliberately simplified approximation of the mainline claim
supersession behavior, **not** a live BEAN Core invocation. The synthetic
ground truth is generated by the environment and is never passed to either
predictor before scoring. Report both stationary and drifting conditions,
including every case-level loss. Neither approach is guaranteed to win.

The arena now includes a rapid-drift, high-signal adversarial condition in
addition to stationary and slower drift. Its purpose is to expose where
evidence accumulation becomes stale. In a 25-seed, 30-step local replay,
the newest-only reference wins that condition (MSE 0.080 versus 0.193).
This is a real failure of the fixed revision prototype on that synthetic
scenario, not a reason to hide or alter the test.

The earlier paired-baseline pilot is kept as a separate reproducibility
fixture; the `runner` executes `arena` for the richer scenario matrix.

## Acceptance condition

For any claimed improvement, save all failures and successes, assess equal
evaluation budgets, compare with the unchanged main baseline, run held-out
tasks and verify across restarts. A win on the synthetic pilot is **not**
a win against any external AI system. Do not merge while external competitions
are described as completed unless their original receipts exist.


## Adaptive volatility pilot (experimental)

`adaptive.py` reuses the existing `RevisableBelief` receipts. It detects
recent disagreement between noisy observations and chooses either the original
source-aware revision estimate or the original newest-only estimate. The
switching rule does **not** receive ground truth, scenario names, or future
observations. This is a small heuristic, not a new general-purpose neural
architecture, and it does not run OpenNARS or any other external system.

`adaptive_benchmark.py` chooses a single volatility threshold from a fixed
five-value grid using only seeds 0 through 19. It freezes that threshold and
evaluates unseen seeds 20 through 79 across stationary, seven-step drift, and
alternating rapid-drift environments. Each arm receives the same observation
stream. The scorer preserves all 24,000 cases, including 18,000 held-out cases,
per-case failures, predictions, mode decisions, the original arena digest and
a canonical SHA-256 receipt. The CI artifact is gzip-compressed and checked
for exact round-trip recovery.

Reproduce locally with:

    python -m unittest bean.tests.test_cognitive_gauntlet bean.tests.test_cognitive_adaptive -v
    python -m experiments.cognitive_gauntlet.adaptive_benchmark --seeds 80 --training-seeds 20 --rounds 100

Initial **local** replay selected threshold 0.75 on training seeds. Held-out
aggregate mean squared error (lower is better) was 0.153899 adaptive versus
0.180541 fixed revision and 0.222833 newest-only. Adaptive lost narrowly
to revision on stationary (0.126681 vs 0.124714) and slower drift
(0.221637 vs 0.218435), while improving rapid drift (0.113379 vs
0.198473). These are seeded synthetic tasks, not a comparison with an
installed external AI, not a deployed BEAN Core improvement, and not proof
of AGI. Results are conditional on the preselected environment families;
additional unseen families and a real Core adapter remain necessary.


## Frozen-policy out-of-family falsification

After choosing threshold 0.75 on the original training seeds, `stress.py`
tests four **new** environments on independent seeds 80 through 139. No
threshold re-selection occurs. Its 24,000 case-level receipts are retained
alongside the original 24,000-case training/held-out replay.

Local results, mean squared error (lower is better):

| New regime | Fixed revision | Adaptive | Outcome |
| --- | ---: | ---: | --- |
| Weak stationary signal | 0.241438 | 0.250721 | Adaptive regresses |
| Weak alternating signal | 0.263388 | 0.260310 | Small adaptive gain |
| Stochastic drift | 0.161132 | 0.160409 | Small adaptive gain |
| Stable then abrupt flip | 0.084187 | 0.084784 | Adaptive regresses |

These are **out-of-family stress tests**, not external model matches.
They demonstrate that the adaptive switch is not uniformly better.
Do not retune the threshold against these results and then continue to
call the same cases independent holdout evidence. The next experiment
should investigate calibration and false-positive volatility switches on
newly preregistered conditions.


## BEAN-native SpongeTD 3x3 policy, independent from reference solver

`rubiks3_sponge.py` reuses the existing **BEAN Core SpongeTD Q-learner**
(`bean/optimization/sponge_td.py`), 18 legal half-turn-metric actions and
`rubiks3.py` legal facelet transitions. It is not a wrapper around cubejs,
the bounded search solver, or the inverse scramble recipe. During training,
self-play generates legal states; the learner explores legal transitions
between observed states and receives a reward **only for reaching SOLVED**.
The policy chooses moves using its frozen learned action-values. On an unseen
state it may use one legal transition to consult learned successor values,
but it does not run a goal search. It stops on absent learned value or a
cycle, not an arbitrary solution-move ceiling. The reference search is called
**after** policy evaluation solely to provide an unchanged comparator.

Reproduce the independent tests and exact case-level receipts:

```bash
python -m unittest bean.tests.test_cognitive_rubiks_sponge -v
python -m experiments.cognitive_gauntlet.rubiks3_sponge
```

The command writes `cognitive-gauntlet-results/rubiks3-sponge-td.json`
with training episodes, seeds, complete move sequences, holdout exclusions,
all successes and failures, independent solved-state replays, source hash,
Q-table SHA-256 and conventional reference comparisons. It also saves the
scored compressed SpongeTD policy in an append-only SQLite journal, which
is reopened in the tests to verify that the same frozen policy reproduces
the solutions. The GitHub Actions matrix uploads both files as artifacts.

**Local Linux Python replay, before exact-head CI**: 250 self-play training
seeds (0..249), 1,138 observed states, 2,752 observed legal transitions,
33,024 TD updates; 50 predeclared heldout seed/length combinations
(seeds 1000..1009, lengths 3, 4, 5, 6, 20). Two states were excluded by
the preregistered train-overlap / duplicate-state rule, leaving **48
independent unseen starting states**. The BEAN-native frozen policy solved
**7/48**, all independently replayed, and matched the proven optimal HTM
length on those seven. By scramble length: 3 turns 5/8, 4 turns 2/10,
5 turns 0/10, 6 turns 0/10, 20 turns **0/10**. The untrained policy solved
0/48; unchanged conventional bounded search (depth 6) solved 38/48.
The learned policy therefore does **not** solve arbitrary full-length
3x3 challenges, and this is not a BEAN Core production integration or
evidence of AGI. Source, case-level failures and training/holdout boundaries
are preserved rather than silently replacing failures with search answers.
