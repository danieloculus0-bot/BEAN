Why BEAN feels different

Not just memory.
Memory with evidence.

BEAN is aimed at a stricter kind of reasoning workflow: not simply storing context, but preserving the trail behind a decision and making changes inspectable over time.

🧠

Persistent event history

SQLite-backed sessions, events, trace IDs, and durable state that a host application can inspect after restart.

🌿

Evidence and uncertainty

BEAN can preserve contradictions, uncertainty, source boundaries, and unresolved states instead of pretending everything is settled.

🔎

Reviewable reasoning

Models can propose. Hosts still control policy, execution authority, and whether a proposal gets accepted, held, or rejected.

Daily Exception Brief

Give BEAN an existing, authorized local export ledger. He prepares a private, read-only morning brief instead of making you hunt through separate reports. Run this from the Bridge checkout after setting PYTHONPATH=src (see the setup guide).

  • Shipment-line OTD, overdue-work evidence, RMA status and gaps
  • Prioritized questions when dates, quantities or source coverage disagree
  • Earlier-versus-current snapshot differences, without invented causes
  • Local HTML + JSON output; unverified figures display N/A
python -m ezbean.daily_brief --database ./private/site.sqlite --site SITE_A --start 2026-10-01 --as-of 2026-10-10T12:00:00Z --out ./private/morning.html

BEAN Core · Offline demonstration
🧠

Memory that survives a restart

BEAN opens a real SQLite database, records an observation and review-required proposal, shuts down, and opens a second session to prove the original records survived.

  • Two separate sessions against one temporary database
  • Verifies the original event and pending proposal remain stored
  • Checks session history and that review was not silently bypassed
  • Fails visibly if any required continuity record is missing
python -m examples.restart_continuity

Two things BEAN refuses to fake

Missing information is not zero.

Quickstart

Run BEAN in a few minutes

This local demo uses a temporary SQLite database and a mock reasoning provider. No API key, no external data source, no hardware control. 

git clone https://github.com/danieloculus0-bot/BEAN.git
cd BEAN
python -m pip install psutil
python -m examples.quickstart_reasoning

What this quickstart proves

  • BEAN records an observation and persists a proposal path.
  • Trace IDs are preserved for later inspection.
  • Review boundaries remain explicit.
  • The architecture can run offline and locally.

Want proof of persistence? Run the follow-up in the same checkout:

python -m examples.restart_continuity

This second demo uses two BEAN sessions and a temporary SQLite database to verify that the original event and pending-review proposal survive closing and reopening.
