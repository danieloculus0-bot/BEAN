Why BEAN feels different

Not just memory.
Memory with evidence.

BEAN is aimed at a stricter kind of reasoning workflow: not simply storing context, but preserving the trail behind a decision and making changes inspectable over time.

🧠

Persistent event history

SQLite-backed sessions, events, trace IDs, and durable state that a host application can inspect after restart.

🌿

Evidence and uncertainty

BEAN can preserve contradictions, uncertainty, source boundaries, and unresolved states instead of pretending everything is settled.

🔎

Reviewable reasoning

Models can propose. Hosts still control policy, execution authority, and whether a proposal gets accepted, held, or rejected.

Inspectable behavior

Two things BEAN refuses to fake

Missing information is not zero.

If a source report is absent, stale, or lacks confirmed coverage, BEAN can preserve the uncertainty instead of inventing a neat-looking answer.

Watcher behavior
current_value = N/A

Read the Watcher contract →

A model’s assertion is not evidence.

An unsupported answer does not get to certify itself. A host-supplied verifier must corroborate the claim before a new definition is recorded as revised knowledge.

Quickstart

Run BEAN in a few minutes

This local demo uses a temporary SQLite database and a mock reasoning provider. No API key, no external data source, no hardware control. 

git clone https://github.com/danieloculus0-bot/BEAN.git
cd BEAN
python -m pip install psutil
python -m examples.quickstart_reasoning

Read the full getting-started guide →

✨

What this quickstart proves

  • BEAN records an observation and persists a proposal path.
  • Trace IDs are preserved for later inspection.
  • Review boundaries remain explicit.
  • The architecture can run offline and locally.
🧾

What it does not claim

  • No proof of general intelligence.
  • No live ERP integration.
  • No independent external fact verification.
  • No autonomous hardware control.
