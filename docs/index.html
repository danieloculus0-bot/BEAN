Neural AI · Actual architecture, not marketing

Yes, BEAN uses a neural network.

A real neural language model handles optional inference through locally installed Ollama. BEAN supplies the persistent context, structured proposal handling, evidence checks, uncertainty and audit trail around that model. Neural inference and durable reasoning work together, but they are not the same subsystem.

Implemented: neural-model inference Not claimed: native BEAN-trained weights or backpropagation

What actually happens when BEAN reasons

  1. 01 · ContextRemember the observation

    Build bounded context from BEAN records, including session history, known claims and explicit uncertainty.

  2. 02 · Neural inferenceAsk a real model

    Opt in to a local Ollama model, such as Qwen. The separate OpenAI provider is also implemented for configured use.

  3. 03 · Evidence gateCheck the proposal

    Parse the model's structured reply and apply filters. Invalid responses or unavailable providers are recorded, not passed off as verified results.

  4. 04 · ContinuityKeep an inspectable record

    Save proposal and model metadata in SQLite, with review required. Inference alone does not grant permission to execute code or control hardware.

Core main · Durable learning mechanics

What BEAN actually retains

SQLite records observations, proposals and evidence history. The source-improvement laboratory additionally records candidate code, test outcomes and prior failures so an interrupted experiment can be resumed. Those records do not modify neural-network weights.

See the source-growth lineage · See persistent-memory proof
Neural network versus native neural training: BEAN currently orchestrates external or locally hosted trained neural models; it does not claim a separately trained BEAN foundation model, its own backpropagation engine or general autonomous intelligence. The model-generated code-repair studies are bounded experiments, not evidence of universal self-improvement. Read the readiness boundaries.

Why BEAN feels different

Not just memory.
Memory with evidence.

BEAN is aimed at a stricter kind of reasoning workflow: not simply storing context, but preserving the trail behind a decision and making changes inspectable over time.

🧠

Persistent event history

SQLite-backed sessions, events, trace IDs, and durable state that a host application can inspect after restart.

🌿

Evidence and uncertainty

BEAN can preserve contradictions, uncertainty, source boundaries, and unresolved states instead of pretending everything is settled.

🔎

Reviewable reasoning

Models can propose. Hosts still control policy, execution authority, and whether a proposal gets accepted, held, or rejected.
