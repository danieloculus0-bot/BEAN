Its Python Core now integrates native reasoning and learning services; broader autonomous intelligence remains a research goal, not an established capability.

Intelligence knows when not to reinvent the answer.

BEAN's Python Core now has a conservative counsel-arbitration policy. When a credible, adequate existing answer is supplied, BEAN can recommend adopting it without calling a model. When knowledge is insufficient, it can flag the need for expert review or further investigation. Reuse is a success, not a failure to innovate.

01

Adopt what works

Prefer an adequate, current, source-linked established method rather than inventing alternatives for novelty.

02

Know the limit

If claimed qualifications, scope, evidence or corroboration are insufficient, recommend verification, counsel or investigation instead of unsupported certainty.

03

Remember outcomes

Retain accepted and rejected judgments in the existing SHA-linked BEAN journal. Positive and negative host feedback survives restart; automatic credibility calibration remains future work.

This is a deterministic, source-aware decision mechanism, not authenticated expert verification, semantic truth determination or general intelligence. Source confidence and qualifications are still host supplied.

Reinforcement learning and reproducible evaluation.

BEAN Core now contains the tested SpongeTD tabular Q-learning engine and optional SpongeDQN neural learning code with replay, target network and restorable checkpoints. The native reasoning experience and strategy-selection service is integrated into the default Python Core startup with optional external inference: it records feedback, compares contextual reasoning strategies, remembers the measured choice, and applies matching lessons on subsequent tasks. The hosted connector and apps are not automatically wired to that local service. Trained synthetic game policies do not prove general cognition, cross-domain transfer, or profitable trading.

The architecture · Scored memory and neural search

A better decision needs better evidence

Observe. Let the policy act and receive a measurable reward.

Learn. Update tabular Q-values or neural-network weights through actual training.

Evaluate. Compare against conventional learners on separate validation games.

Remember. Score the evidence, compress weights, then file their SHA-256 identity and journal receipt.

Recheck. Reject underperforming candidates and test adopted policies on a sealed holdout.

SHA-256 verifies recorded bytes, not whether the underlying observation was true. Neural evolution is experimental and has not demonstrated consistently superior learning.

SpongeDQN · Real PyTorch neural training · Research branch

The Q-network was already here.

SpongeDQN uses a 3 → 64 → 64 → 3 multilayer network on a three-value engineered Breakout state. It performs genuine gradient updates via PyTorch, keeps a replay buffer, uses a periodically synchronized target network, and can restore SHA-256-identified compressed neural weights from its research journal.

Network. Two 64-unit hidden layers; three actions: left, stay, right.

Learning. Replay minibatches, target Q-values, backpropagation and optimizer updates.

Persistence. Scored neural weight capsules and restart/recovery checks.

Comparison. DQN versus SpongeTD tabular Q-learning versus a cold policy on separate synthetic holdout games.

This is existing, runnable experimental code, not a proposal or merely a diagram. It is not pixel-based Atari, a general-purpose LLM, a trained semantic ledger ranker or a production BEAN Core capability. The neural-evolution experiments above include losses; no overall superiority is claimed.

Bridge Lab009's revised synthetic experiment distinguishes knowledge retained across a restart from a novel answer acquired during evaluation. Four Windows/Linux Python-version jobs passed the targeted learning-loop CI matrix.

Separately, BEAN Core selected a tested SQLite indexed-recall strategy over repeatedly scanning compressed archives. In the synthetic 1,200-case benchmark, retrieval was 11.3×–39.5× faster across four CI environments; all imported cases remained exact and failures were retained. Warm-query speed is not end-to-end performance.

New experimental reward adapter: BEAN can receive a bounded JSON view of the historical scoreboards and compute a signed reward for a matched performance change. Positive = improvement; negative = regression; zero = verified tie; unavailable = no justified comparison. The same evaluation receipt cannot mint additional credit simply by changing run labels. See scoreboard/reward PR #141.

The ledger, scoreboard reader and reward adapter remain research-only; the connected BEAN memory plugin and neural learner are not yet wired to this reward source. Historical CI artifacts may expire and some case details are not archived long-term. This is not evidence of neural policy improvement or a trained semantic retrieval ranker.
