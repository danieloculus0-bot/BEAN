The rules and the scoreboard

Allowed: U, D, F, B, R, L turns, each clockwise, counterclockwise or 180°. Every turn counts as one move (half-turn metric).

Reference: unmodified, MIT-licensed cubejs two-phase solver, in a background worker. Every valid 3×3 state is within its documented 22-move search bound. This is not an arbitrary eight-move cutoff.

Candidate: a six-move shortest-path probe plus case-based route memory learned from verified solutions in this browser. It tries to improve the reference move count, then independently replays every candidate.

The six-move probe only checks for shorter solutions. It does not cap the reference solver. Cubejs is a conventional algorithm, not a learned BEAN agent. Remembered routes persist in this browser only, not BEAN Core.

Session receipts

    Session receipts keep successes and failures. Verified case routes are reused and stored in browser local storage. They are not sent to BEAN Core or trained into model weights.

    What does this prove?

    We test a conventional full-cube solver against a small, explicitly separate route-learning candidate without giving either one the inverse scramble. A learned route wins only if it uses fewer valid face turns than the same-position reference, and each result is verified by independent sticker-level replay. This is case reuse, not evidence of general intelligence or learned model weights.

    Try the Shortcut example: three legal turns create a position that can be solved in one. The search discovers the one-turn answer from the position alone. For arbitrary long scrambles, a shorter answer is not guaranteed. The solver can use more than eight moves, and the candidate can lose or tie.
