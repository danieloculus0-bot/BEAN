BEAN research update · October 21, 2026

BEAN learning: methods and results

Lab027 uses the existing SpongeTD reinforcement-learning implementation. Its trained policy was evaluated on new procedural puzzles and tested on Windows and Linux. Source code, evaluation methods and test logs are available below.

Lab027 · Unseen-map learning experiment

Training improved navigation efficiency.

After 3,000 training puzzles, the trained policy solved 237 of 240 new map layouts using Q-learning with short-term loop avoidance. The untrained comparison used identical loop-avoidance settings.

98.75%New maps solved with trained Q-learning and loop avoidance
68.5%Fewer average moves than the untrained control
7,380Individual scored episode records in a lossless event ledger

Both Windows and Ubuntu passed the GitHub CI run at commit 4d969b0e. Results apply to this procedural puzzle family and do not establish general-purpose reasoning.

Lab026 · Native BEAN reasoning skills

Memory and strategy selection.

Lab026 extends BEAN's existing evidence journal and evaluation system with capabilities to:

  1. Retrieve the right experience
  2. Reflect on the last failure
  3. Reuse a successful procedure
  4. Compare strategies and retain the measured winner

One connected ecosystem

Different tools. Shared direction.

The planned architecture brings engineering records, manufacturing workflows and evidence-based AI tools into a shared system. Shared code and integration tests do not automatically mean that every standalone app is synchronized in production.

01 / Make and verify

Engineering layer

ForgeVault manages file versions. EZ-FAIR proposes inspection characteristics. EZ-FEA investigates structural models. EZstimate prepares traceable quotes.

02 / Run the operation

Axiom / JERP layer

Quality, maintenance, methods, workforce research, production and purchasing are being organized into a coherent ERP architecture.

03 / Observe and learn

BEAN intelligence layer

Persistent source-aware reasoning, experimental learning, evidence bridges and independently checkable results. Integration is verified feature by feature.

The fine print matters

Project status and limitations.

These projects include released source, browser demos, local beta software, experimental research and architecture plans. A browser simulation does not imply access to an actual ERP, wallet, physical robot or engineering solver. Automated test results apply only to the code revisions and checks explicitly identified; they do not establish production readiness.

The repositories are public to inspect. Public visibility does not automatically grant redistribution rights. Check the license in each repository before reuse. For current build evidence, follow each project's README and GitHub Actions.
