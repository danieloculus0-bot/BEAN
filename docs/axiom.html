A different approach to enterprise software

Keep the spreadsheet.
Connect the company.

People should not need to memorize ten applications—or operate a business out of a maze of disconnected private workbooks. Axiom is building one place for manufacturing and operations. BEAN provides evidence-aware decision components. Language connectors help people find and use the tools without forcing a local language model onto every workstation.

The document remains useful

Excel can stay Excel.
Axiom makes the information usable.

The goal is a lightweight native viewer/editor for Excel-compatible files. Employees can inspect and edit familiar workbooks; Axiom keeps a controlled original and proposes structured imports of the rows that matter. Review comes before shared business records change.

01

Open and edit

Use a familiar Excel-compatible interface instead of inventing another spreadsheet engine. Keep workbook tabs, formulas, formatting and the original file.

02

Interpret and map

Recognize candidate tables, headers, dates, part numbers, employees, jobs or transactions. Show column mappings and uncertainties before importing.

03

Share approved facts

Move accepted records to their owning Axiom module, with document revision, identity, provenance and import receipt. No silent replacement of a system of record.

Intelligence where it matters

BEAN thinks.
Connectors communicate.

BEAN Core's role is to maintain evidence, remember outcomes, select strategies and support inspectable decisions. Natural-language services can explain those decisions and route people to the correct screen. Keeping language inference outside the device lets lightweight workstations focus on application services.

For example, “Add Quality Forge to my Favorites” can map to a real Axiom module key, save it in Axiom's database, and confirm success only after the write is acknowledged. No staged chat response is necessary.

A single recognizable workspace

Dark graphite, electric-lime controls, repairable hardware targets, browser-accessible modules and deep links into the records employees actually use.

One important boundary:

We have tested the local BEAN-to-Axiom navigation connector. Connecting that tool to an authenticated remote ChatGPT session—particularly on phones—still requires a hosted identity and network pathway.

Affordable compute

Jetson-ready in direction.
Not yet Jetson-verified.

JERP's JetPack deployment target uses an ARM64 native office editor, a browser-based Axiom shell and lightweight BEAN services. A language model is optional, not a system requirement. Native LibreOffice Calc is a practical office-app candidate for supported Linux distributions; compatibility and editing fidelity still need hardware tests.

Original Jetson Nano note: NVIDIA's final Nano-supported JetPack is 4.6.6 on a legacy Ubuntu 18.04 base. We'll distinguish that target from newer Orin boards, and won't pretend one installer works equally on all Jetsons.

Design principle

Use the device for the actual job. Don't burn the memory budget running a local LLM just to speak a sentence.

Office and file-editing integration is a compatibility feature. Axiom remains the owner of approved company records; a workbook never silently gets to override them.
