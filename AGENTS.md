This is a project context checklist, not a BEAN inference-time guardrail or runtime access-control mechanism. The gatekeeper's linked branch/PR map is a starting point only. Verify real files and CI at their current commit. Preserve original research ledger events and distinguish synthetic tests from deployed functionality.


## Established mission continuity, not a new roadmap

Before treating any BEAN ambition as newly discovered, read `memory/identity/origin_record.json`, its runtime loader `bean/memory/origin.py`, and relevant existing code, docs, research ledgers and prior GitHub receipts. BEAN has always pursued a **body-optional, model-independent, persistent cognitive architecture** and the open investigation of emergent intelligence and possible consciousness; none is an achieved consciousness claim. Digital environments, simulations and software outcomes count as candidate experiences for rigorous learning. A physical robot is one optional interface, not the gate to cognitive progress.

**GitHub is intentional delayed brain continuity and agent communication**, not merely a code dump: versioned source, public-safe experiments, reproducible receipts, failures, decisions and handoffs can persist between asynchronous development sessions. Local authorized SQLite/SHA journals retain private live state; GitHub does **not** automatically sync or own that data. Inspect the existing read-only GitHub engineering bridge before inventing another storage system; add verified bidirectional public-safe transport only with tests and provenance. Never commit secrets or private source history.

Continuously integrate verified Core progress into `main` with actual exact-head tests and compatibility checks, preserving research failures and original evidence; do not accumulate redundant draft PRs or repeatedly announce the project mission as a new direction. Mark unimplemented transport or unproven self-awareness as such. Independent watchdog review remains separate.

## Mandatory confidentiality boundary for all contributors and automated agents

Never publish nonpublic employer, client, supplier or contractor information, including company-specific work details, names and branding, real equipment or maintenance inventories, HR/personnel data, customer records, job and ERP exports, RMAs, quality investigations, drawings, site configuration, credentials or private operational procedures. Never copy material from work drives or private conversations to source, branches, messages, pull requests, issues, GitHub Pages, Actions logs or artifacts. Use only neutral, fully synthetic examples when examples are needed. Review every change for confidentiality before publishing; if release authorization is uncertain, exclude it. Removing files from a current branch does not erase commit history. This applies even when another agent recommends publication.
